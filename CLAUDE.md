## What this addon is now (19 Sep 2026)

The second addon of this name. The first was 5,000 lines of shaman Chain Heal brain, ranked out of the combat log; it is tagged `tbc-final` and is not coming back. Nothing in this folder is for TBC any more, and no file here may read a number the client calls secret.

## Layout (BiSHealing only)

- `BiSHealing.toc`: the load order, and the only place the version lives (`## Version`, currently `0.1.0`). It claims `## Interface: 20506, 16001` — both censuses, so the fence judges both. `## SavedVariables: BiSHealingDB`, `## OptionalDeps: BiSTheme, Blizzard_AuraContainer` (the aura containers belong to Blizzard's own addon; without the dep line, building one is a protected action and the client pops a dialog at every layout).
- `Lockdown.lua`: loads first and answers the questions that decide everything else — `NS.SECRET` (does this client hide its numbers), `NS.Blind()` (are we inside the lockdown, where auras and cooldowns go secret too), and since 19 Sep **`NS.Secret(v)` / `NS.Plain(v)`**, which wrap the client's own `issecretvalue`. Use those for any value that goes into an `if` or indexes a table: a secret boolean refuses the test itself, and a secret string refuses to be a table key. Feature-detected through `C_Secrets`, never a build number.
- `Core.lua`: the saved variables (`NS.DB`, `NS.DBVER` 1, with the one-time migration out of the old addon's table), `NS.Print`, `NS.VERSION` read from the TOC, **`NS.DO`** and the slash command. `NS.DO` is the table of everything the addon can be asked to do; the slash command, the minimap menu and the options window all go through it, so the three doors cannot drift. `/bish`, `/bisheals` and `/bishf` all reach it — the last is an alias kept because it is what has been typed here for a week. **`NS.SHORT`** (6 Nov 2026) is every command's short word (4 letters or fewer); `NS.Expand` turns a short first word into its long one before the parser reads it, so the parser keeps one spelling. `NS.Mark()` is the version mark ("0.16.0  <sha> <MMDD-HHMM>" on a copy deploy.sh stamped), shown in the bind window's bottom-right corner.
- **The secret alpha (8 Nov 2026, Arn: "a hidden switch in the release")**, Core.lua: test features ship OFF and UNLISTED - never in `/bish help`, the options window, the BiS> page, the CHANGELOG or the CurseForge page. `/bish alpha on|off` (account `alpha`), `/bish alpha` lists them, `/bish alpha <key> on|off` (`alphaOff[key]`). A feature registers with `NS.AlphaFeature{ key, name, desc }` and asks `NS.AlphaOn("key")` at the moment it acts. `NS.AlphaHello` prints one amber line at login while it is on. Not in the API on purpose.
- **`Radar.lua` (`NS.RD`), the secret alpha's first feature (8 Nov 2026; mockup https://claude.ai/artifact/6FVpu5JR4yCyyaHT1VfftP):** `NS.AlphaFeature{ key = "radar", apply, cmd }` - while `NS.AlphaOn("radar")` it stands in for the grid (`FG.Hidden(d)` = the saved `shown` OR `RD.Active()`; `shown` is never written). `BiSHealingRadar`, a square. `RD.Geometry(raid, ownGroup)`: a party = 5 spokes (`RD.PARTY`); a raid = 40 FIXED slots by group and place (`RD.RAID`): your group the top sector, nearer the middle and bigger, the other 7 clockwise on the outer ring. `RD.Roster()` maps units to slots; `RD.Spoke(i)` makes a spoke on first use, `RD.PlaceSpoke` places it. Each spoke: a HEAL pip (SecureUnitButton; `type1`/`spell1` = `RD.Heal()` - the class heal's top rank minus 2, `db.radar.heal` overrides; other clicks = `FM.ApplyTo`), coloured by `UnitHealthPercent(unit, true, RD.Curve(amber))` (gone >=90%, green, amber below `1 - heal / max health` learned out of combat else 80%, red <35% + `RD.RedCurve` pulse layer); CURE pips (one per `FA.Cures()` cure: an AuraContainer marker - a diamond in the cure's colour - and a secure box; reused by place); a BOGEY (their target, `*harmbutton1` kick from `FG.KickCast`, alpha 1 only while `FG.Casting`; in a raid your own group only); a range arc (`RD.PaintRange`, the client's ternary on a secret) and an LOS flash (UI_ERROR_MESSAGE on the spoke under the mouse). **The FUEL GAUGE** (8 Nov, `buildGauge`, `RD.gauge`, left edge, `RD.GAUGE`): vertical StatusBars handed untouched - the boss's health (`RD.PickFuel`: boss1, else a hostile target; `bossLayer` alpha, a secret hostile via SetAlphaFromBoolean; out of a fight only boss1) in red, your mana over it in green, ticks 25/50/75, a magenta caret on the boss fill's TOP; BINGO = a ruler (your mana, lifted `RD.BINGO` 30% in a clipped frame) whose fill top is the FLOOR of `hotClip`, which clips a hot pulsing boss copy + flag (shows exactly where boss > mana + 30%); a cyan chevron (`RD.PaintRegen`, Regen.lua's own clock + remembered while-casting share, in a fight only). **The MANA COLUMN** beside it (`RD.COLUMN`, x `RD.COLUMN_X`, 22px pips): STABILIZER (`FS.Target()` buff: the red gyro always under, the client's aura button with a green gyro over it), MANA TIDE / POTION ("Restore Mana") / DRINK (`RD.ArmTools`: each learns `at` = 1 - restores / max mana from its own words out of a fight, `RD.ToolCurve(at)` on UnitPowerPercent lights it; drink out of a fight only; 0.5 + `guess` when unknown), RATIONS (BiSToolsAPI.FoodNow, else Well Fed missing). The missile tape is gone. **Everything lit pulses** (`RD.Pulse` on a wrapper frame: soft / `PULSE_MID` amber / hard red + bogeys) and carries the **GCD sweep** (`RD.Sweep`, fed one 61304 object in `RD.Sweeps`; Mana Tide and the potion their own; a colour-lit face's swipe tinted by `RD.SwipeCurve`). Out of combat the scope (`RD.scope`, drawn at party size and SCALED for a raid) and the dim places (`RD.dims`) show; in a fight `RD.PaintQuiet` puts them to alpha 0. Secure writes only in `RD.Arm` out of combat (`RD.pending` queues; PLAYER_REGEN_ENABLED runs it). A ticker `RD.TICK` (only while active) runs `RD.Look`. Drag ends at PLAYER_REGEN_DISABLED / OnHide (`RD.EndDrag`). Hidden words: `/bish alpha radar heal <spell>|default`, `scale <50-200>`, `center`. The suite's mock now REFUSES Show/Hide/SetShown/SetAttribute/EnableMouse on any Secure-template frame in combat (`lockdownGuard`; the client's own unit watch and state driver go round it via `f.__client`).
- `Grid.lua`: the cells. `FG.Roster` (group order, never health order), `Make`, `Bind`, `Layout`, `Paint`, `Start`. **The rule this file exists to keep: the value the client gives is handed on untouched** — into `SetValue`, into a font string, never into arithmetic or a comparison. That now covers `f.incoming`, the heals-on-their-way bar, which is anchored to the health bar's *texture* so it starts where the fill ends. **`f.healAbsorb`** (8 Nov 2026, VuhDo's idea): `UnitGetTotalHealAbsorbs` handed untouched to a bar built like the overheal - one TOPRIGHT anchor on the fill's end, reverse fill, the health's 0..max scale, `curMask` trims it to the filled health; `FG.HEAL_ABSORB` dark maroon in both looks, a white `f.healAbsorbTick`; `UNIT_HEAL_ABSORB_AMOUNT_CHANGED` marks the cell; `/bish healabsorb [test]` (`habs`, `FG.healAbsorbTest`). It holds no spell names; "can I reach them" asks `NS.FM.RangeSpell()` (whatever is on the left button) through `C_Spell.IsSpellInRange` — the bare global does not exist on 1.60.1. `FG.Layout` is defined twice: the second (the one-at-a-time wrapper) wins and calls the first. **PvP mode (8 Nov 2026, setting `pvp` = "off" | "bg" | "on", default "off" for everyone; `/bish pvp`, short of `pvpmode`):** while `FG.PvPActive()` (on, or bg inside IsInInstance "pvp"/"arena") the grid keeps the saved layout (Arn, 8 Nov: forcing columns was confusing) - every layout leaves `extra` = PVP_W + PAD on each cell's right, each cell keeps `cellX/cellY/cellW/cellH` - and each member gets a target cell on its right a quarter wide, placed from those (`FG.MakePvP`, SecureUnitButtonTemplate, unit `<member>target` / "target" written once at layout, RegisterUnitWatch, `NS.FM.ApplyTo`). The cells in use are `FG.pvpCells` (emptied in place when off; Mouse.lua's `FM.Apply` walks it), `FG.pvpByUnit` maps member -> cell. Paint (`FG.PaintPvPCell`): health handed to a thin bar untouched, red/green from UnitCanAttack (secret -> the client's curve), 4 letters of a plain name. `FG.PvPFocus`: the plain GUID on 2+ cells and more than any other (not a friend, no tie) gets a gold edge. UNIT_TARGET / PLAYER_TARGET_CHANGED (heard only while it shows) repaint one cell; `FG.PvPTick` repaints all 4 a second from the update loop, nothing when off. It rides the macro as `PV=1|2` (Keep.lua; restored in `FK.Load`). (Since 1.0.2 the target cell is HALF a cell wide, `FG.PVP_CHARS` 6, and carries your class's interrupt: `FG.KICK`, a SecureActionButton `c.kickFx` casting `FG.KickCast()` on an ENEMY only through `*harmbutton1` = "kick", dim until `FG.Casting(tok)` - UnitCastingDuration / UnitChannelDuration, `type()` only - then the cast alert `FG.KickFx()` glow / bounce / both.) **THE COCKPIT LOOK (1.0.3, 8 Nov 2026; Arn: "reimage the cells and frames as if its on a cockpit"):** `d.look` = "cockpit" (new installs) | "classic" (everyone who had the addon before; nil still reads as cockpit, so the look is always WRITTEN: `NS.Forever10` writes it for a save it stamps, `NS.LookStamp` once - stamp `look103` - writes classic into a save stamped at 1.0 with no look; Arn's cousin, 8 Nov) (`FG.Look`, `/bish look`, options row "look"). Each cell keeps `f.__look`; `FG.ApplyLook(f)` dresses it (tile, bezel, `f.lamp` class lamp, Arial Narrow, `FG.COCKPIT` colours: green / amber / red by state, cyan incoming, white shield, orange overheal, magenta target) and in the cockpit lifts the tank / target / mouse marks over the ink. **Design B, the tape** (Arn picked it of three drawn; A "dim instrument" is kept for Chain Heal mode): `FG.ShapeTape(f)` puts `f.bar` as a `tapeH` tape along the bottom in `f.track` with three quarter marks `f.ticks` (on `f.bandFrame`, between the bands and the words), `f.ink` over the WHOLE cell, `f.htext` amber just above the tape on the right; no strip (`f.band`) and no box (`f.readoutBox`) - both kept hidden. `FG.SizeBands(f, w, h)` sizes incoming / absorb / overheal / healAbsorb to the bar (the tape in the cockpit) - the overheal's geometry needs them equal; every sizing site calls it. Classic restores every value, anchor and level. `FG.RedressAll` on a switch. Paint: cockpit = by health always, white names, the class on the lamp.
- `Auras.lua`: markers the client draws for auras we may not read (`AuraContainer` + `CustomAuraContainerTemplate`). The dispel slot asks for `HARMFUL|RAID_PLAYER_DISPELLABLE` and narrows it with **nothing** — the client's own answer covers whoever is playing. `FA.WATCH` is an empty switch. `FA.Debug` marks every debuff, to tell "the markers do not draw" apart from "you cannot cure that".
- `Mouse.lua` / `MouseUI.lua`: every click meaning in one place. Buttons 1-5 are secure attributes on the cells; the wheel is a *binding*, so it goes through a hidden secure button holding `/cast [@mouseover]`. Both are refused in combat and queued. Binds keep their **rank** (`Name(Rank 3)`), and the icon is looked up without it. `FM.CLASS_DEFAULTS` is the only class-shaped thing in the addon. **Hostile binds (8 Nov 2026):** a second mouse under keys `FM.HARM .. mod .. slot` ("harm:shift-left") in the same `binds` table; on a cell, `harmTo` writes `<mod>harmbutton<n>` = "harm<n>" plus `<mod>type-harm<n>` etc., so the client's own secure click switches to them on an enemy (nothing of ours runs at the click); the wheel's one macro puts `/cast [@mouseover,harm,nodead] X` + `/stopmacro [@mouseover,harm]` before the heal. `clearOurs` takes every attribute of ours off (res, Clique). **Macros:** `FM.CursorMacro` reads ("macro", index) off the cursor into `"macro:<name>"` (names with ; # = : ( ) refused), run through the secure `macro` attribute; `FM.MacroOf`. MouseUI's `w.sets` = heal | hostile, `w:Key()` = side .. modifier, hostile slots tinted `HARM_BG`, no trinket ticks or heal palette on that side. `FM.Apply` also walks `NS.FG.pvpCells`. Keep.lua: hostile rows are THREE-letter codes `x` + modifier (`n` = none) + slot, after every heal row (trimmed first) - a two-letter one would land on an old copy's plain click.
- `Between.lua`: what can be learned when the lockdown lifts (`PLAYER_REGEN_ENABLED`). `/bish scan` asks it now; it owns no slash command of its own.
- `API.lua`: `BiSHealingAPI` (major 1, version 1, playbook 5a), last before `UI/`. Read-only copies of the binds, the show/Clique switches, BiS> now and the tank; `OpenBinds`/`OpenOptions`; callbacks `BiSHealing_BindsChanged` / `_TankChanged` / `_Shown`, fired through `NS.Announce` from Mouse.lua, Now.lua and Core.lua. The file's header is the documentation. Ready = the grid started (`FG.anchor`).
- **Forever 1.0 (7 Nov 2026), Core.lua `NS.Forever10`:** a one-time stamp `forever10` on the account table at PLAYER_LOGIN. A NEW install (no account file, no per-character copy, no BiSHealing macro - `NS.Returning`) gets `NS.QUIET` written (crosshair, LOS flash off, buff sound quiet, `selfBuffs = { none = true }`); an EXISTING one gets its nil-read switches (`NS.FREEZE`: hover, flash) written as true. Until the macro list is in, nothing is decided (UPDATE_MACROS asks again). `/bish hover` and `/bish flash` store true/false - nil never means on again. The red "did not hand back a saved file" line only fires for someone who had a file. `NS.Claim` never copies `dbver` (an alt with no copy used to re-run the migration and reset the account's settings).
- `UI/options.lua`: two columns of rows, all of them `NS.DO` calls, on BiSTheme's shared kit. `NS.UI.Rows()` is what a suite reads back. `CFG.Page()` (PLAYER_LOGIN) registers "BiS> Healing" under BiS> in the game's options (`Libs\BiSTheme\Settings.lua`, minor 3): the page is the kit's dashboard, `T.Dashboard(body, CFG.Model())` (`build` once, `refresh` = `CFG.dash:Paint()`), the family rule - never re-parents, shows or shrinks the options window (8 Nov 2026). `CFG.Entries()` makes its sections out of the window's OWN row tables (`CFG.Tables()`, the `CFG.Sections()` answer made once and kept, which `CFG.Build` uses too), handed `CFG.LIVE` (a proxy onto `NS.DB()` as it is now; a button row that sees it knows it was pressed on the page, puts the game's options away first, and opens the mana window free / the options window with the sound drawer): **frames** (switch = `NS.DO.show`; scale, centre, LOS flash), **binds & clicks** (window button = the mouse binds; Clique, which heal, minimap button), **look** (number, colour, ring, crosshair, dim, markers), **layout** (groups, PvP mode), **target & pets** (the `cells` row's four parts as toggles, pets), **BiS> now** (switch = `NS.DO.now`; the tank mark's three steppers), **buff buttons** (switch = `NS.DO.buffs`; a toggle per `FU.FAMILIES` buff), **buff reminder** (switch = the "watch my buff" row; sound, sound id), **the channel** (switch = LibBiSComm's `SetEnabled`, the one `/biscomm on|off` flips, then `NS.Comm.Save`; share). `CFG.Status()` is its front-page line.
- `UI/minimap.lua`: the shared button (BiSTheme's `Minimap.lua` minor 5): left = the mouse binds, right = `onRight = act("options")` = `CFG.Toggle`, the addon's OWN options window as a toggle (right-click again closes it), never the game's options (8 Nov 2026). Since 1.0 - it was the other way round in 0.17.
- `Libs/`: BiSTheme (`Console.lua`, `Options.lua`, `Minimap.lua`, `Settings.lua`), `RezComm-1.0` and, since 0.13.0, `LibBiSComm-1.0` (booted by `NS.Comm.Boot` at login, its `/biscomm` switches saved as `comm` / `commShare`) — copies, never edited here. See the libs rules in `../_bisdev/CLAUDE.md`.
